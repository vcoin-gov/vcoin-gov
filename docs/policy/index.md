## 这一组解决什么

技术研判能走多远，取决于法律边界划在哪。本组负责把「能不能打、按什么打、跨境怎么打、为什么打不干净」这四个问题说清楚，为链上组和原型组提供**判定口径**而不是泛泛的背景介绍。

## 四篇专题的关系

不是四个平行的选题，是一条推理链：

| 顺序 | 专题 | 回答的问题 | 输出给谁 |
| --- | --- | --- | --- |
| ① | [国内法规与司法解释](./domestic-regulation) | 行为怎么定性？按什么罪名追？入罪门槛在哪？ | 链上组（判定什么算可疑）、原型组（检测目标） |
| ② | [境外监管与跨境差异](./overseas-regulation) | 境外主体受什么管？跨境协作的接口和障碍在哪？ | 组长（对外汇报）、原型组（跨境数据可得性） |
| ③ | [公开通报案例库](./cases) | 实际办案中怎么做？作案模式长什么样？ | 全组（模式提炼）、宣传预警（素材） |
| ④ | [治理痛点提炼](./pain-points) | 现有手段为什么失效？堵点卡在哪个环节？ | 组长（对策建议）、原型组（攻关优先级） |

::: tip 写作顺序建议
先做 ① 和 ③ —— 一个有法条支撑，一个有通报原文，最容易出成果。② 和 ④ 依赖前两者的积累，可以稍后。
:::

## 全组统一口径（写之前先对齐）

- 虚拟货币在我国**不具有与法定货币等同的法律地位**，相关业务活动属于**非法金融活动**——这一点在每篇里都要表述一致，不要各写各的。
- 定罪路径不唯一：同一笔资金流转，可能同时涉及诈骗（上游）、帮信/掩隐（中间层）、洗钱（下游）、非法经营（兑换环节）。写的时候要标明**在哪一层**。
- 区分「明确入罪」和「司法实践中存在争议」。后者必须显式标注，不能混着写。

## 交付要求

| 项 | 要求 |
| --- | --- |
| 形式 | Markdown 正文（本站页面），汇报用 PPT 另出 |
| 篇幅 | 单篇 800–3000 字，超了拆页 |
| 来源 | 法条给全称 + 条号，案例给通报链接或案号 |
| 更新 | 状态标「进行中」就可以发，不必等写完 |
| 时效 | 法规有变动时，在页面顶部加一条「YYYY-MM 更新：…」|
