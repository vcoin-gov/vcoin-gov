# 调研文档模板

新建或改写专题页面时，复制下面的骨架，把括号里的提示替换成实际内容。**骨架本身是交底的**：每一条都对应评审时会问的问题。

## 一、直接复制这段

```markdown
---
title: 专题名称
---

<div class="doc-meta">
  <span class="owner">负责人：@昵称</span>
  <span class="doing">状态：进行中</span>
</div>

## 结论摘要

<!-- 3–5 行讲清这篇的核心结论。让没时间细看的人也能拿走要点。 -->

1. …
2. …

## 背景与适用范围

<!-- 这个专题解决什么问题？适用于哪类币种 / 哪类案件 / 哪个司法辖区？明确不覆盖什么。 -->

## 主体内容

<!-- 按逻辑拆 3–6 个二级标题，每个标题下先给结论再给支撑。 -->

### 分点一

| 维度 | 内容 | 出处 |
| --- | --- | --- |
| … | … | … |

### 分点二

…

## 数据与证据

<!-- 用到的链上地址、交易哈希、数据集、通报原文链接。可复现是底线。 -->

| 类型 | 标识 | 说明 |
| --- | --- | --- |
| 地址 | `0x…` | … |
| 通报 | https://… | … |

## 局限与待验证

<!-- 哪些是推断、哪些没核实、哪些换场景就不成立。这一节不是自我否定，是让别人敢用你的结论。 -->

- 【推断】…（依据：…）

## 下一步

- [ ] …
- [ ] …

## 参考

1. …
```

## 二、每块的最低要求

| 章节 | 不能空着的原因 | 最低标准 |
| --- | --- | --- |
| 结论摘要 | 别人判断要不要读下去的唯一依据 | 至少 2 条可独立成立的结论 |
| 背景与适用范围 | 防止结论被跨场景误用 | 写清币种/辖区/案件类型边界 |
| 主体内容 | 真正的研究产出 | 每个分点必须有事实支撑，不能只有观点 |
| 数据与证据 | 可复现性 | 至少 1 个可点开的原始来源 |
| 局限与待验证 | 让结论可信而不是可疑 | 诚实列出不确定项，别硬凑 |
| 下一步 | 体现这页还在长 | 至少 1 条具体待办 |

## 三、不同专题的侧重

同样是这套骨架，各组的下笔重点不一样：

**政策法规类**：主体内容按「法条 → 司法解释 → 案例适用」三层展开。法条给全称 + 条号 + 生效时间；案例给案号或通报链接；务必区分「明确入罪」和「司法实践中存在争议」。

**链上特征类**：主体内容按「特征定义 → 识别方法 → 阈值/判据 → 误报场景」展开。给不出量化阈值的，写清定性判据和判断人。数据与证据一节必须有真实地址。

**工具调研类**：主体内容按「能力矩阵 → 数据覆盖 → 免费额度/成本 → 局限」展开。对比表是主产出，文字只用来解释表格里看不出门道的地方。

**原型开发类**：主体内容按「要解决的问题 → 方案设计 → 实现要点 → 验证结果」展开。贴关键代码片段和运行结果，不贴整份代码（代码进仓库对应目录）。

## 四、配图要求

- 截图必须能看清关键信息（地址、金额、时间戳），模糊的图不如不放。
- 链上截图建议同时给出对应的交易哈希，方便别人自己复核。
- 流程图、资金树用纯色线条导出 PNG，别用带水印的在线工具默认模板。
- 存到 `docs/public/assets/<页面名>/`，命名 `fig-01-xxx.png`。

## 五、提交前扫一眼

- 有没有任何一段是「大家都知道」的空话？删掉。
- 有没有结论找不到出处？补上，或降级为【推断】。
- 有没有写到具体规避手法？改成识别特征描述。
- 换一个不懂这块的人来读，能不能看懂结论？不能就改写。
