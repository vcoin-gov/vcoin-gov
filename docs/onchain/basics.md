## 一、两种账本模型

### UTXO（比特币为代表）

没有"账户余额"这个概念，只有一堆**未花费的输出**。转账时把若干 UTXO 当输入花掉，产生新输出，找零回到自己。

**对溯源的意义**：

- **共同输入 heuristic**：一笔交易把多个地址的输出一起花掉，说明这些私钥被同一方控制 → 这是比特币地址聚类最经典的方法。
- **找零识别**：输出的其中一个通常是找零，回到自己控制的地址。识别找零能大幅扩展聚类范围。
- **没有 nonce**，交易顺序靠区块内位置和手续费竞价确定。

::: warning 常见误判
共同输入聚类的误报来源是**混币服务和交易所的批量归集**——它们本来就会把很多人的币打进同一笔交易。看到共同输入就断定"同一人"，会得出荒谬结论。
:::

#### 链上示例：一笔「合并 + 找零」的比特币交易

交易 [`66e9d954…90593`](https://mempool.space/tx/66e9d95408a96ead81a36e505015c0ba15598a77c9f1659e38530827b2790593)（区块 976,274，2026-11-17 UTC）：

| 方向 | 地址 | 金额（sat） |
| --- | --- | --- |
| 输入 1 | `13EhPvgr3cyYLqtranPF32EM2H7bFF6BPF` | 463,600 |
| 输入 2 | `13EhPvgr3cyYLqtranPF32EM2H7bFF6BPF` | 285,874 |
| 输入 3 | `13EhPvgr3cyYLqtranPF32EM2H7bFF6BPF` | 256,781 |
| 输出 1 | `bc1qyq75f74nuelpw7xdt3d7mnpwuw2es3awnds0m8` | 193,380 |
| 输出 2（找零） | `13EhPvgr3cyYLqtranPF32EM2H7bFF6BPF` | 798,340 |

读法：输入合计 1,006,255 sat，输出合计 991,720 sat，差额 14,535 sat 就是手续费（516 字节，约 28 sat/vB）。三个输入来自同一地址、找零又回到同一地址，这是**地址复用**，也是找零识别里最强的一类信号。

不是每笔都这么清楚。找零去了新地址时，只能靠脚本类型、整数金额、输出顺序、手续费反推等弱信号推断，必须写明依据和置信度（方法见第九节）。

### 账户模型（以太坊、TRON、BSC 等）

每个地址有余额、nonce（交易计数）、代码（合约）、存储。转账直接改余额。

**对溯源的意义**：

- **nonce 是硬指标**：一个地址的 nonce 就是它发出的交易总数，可以判断地址是新地址还是长期活跃地址。
- **Gas 支付方暴露关系**：新地址的第一笔交易如果由另一个地址代付 gas，两者存在控制或资助关系。
- **合约调用链**：代币转账实际是调用合约的 `transfer` 方法，日志（event log）里有完整记录，比原生转账信息更全。

::: warning 不是所有账户模型都有 nonce
以太坊、BSC 有 nonce；**TRON 属于账户模型，但没有以太坊式的 nonce**，交易顺序靠过期时间和区块引用确定。在 TRON 上不能用 nonce 判断地址年龄，具体见第十节。
:::

#### 链上示例：一笔 ERC-20 转账

交易 [`0x7275cd77…cf670`](https://etherscan.io/tx/0x7275cd77d3bb294183b01c88259fc39c6bd2669ef3b1bc49583e5d04e63cf670)（区块 26,434,892）：

| 字段 | 值 |
| --- | --- |
| from | `0x0314f88c60461e3092a1815f86688c3c0df573c1` |
| to（合约） | `0xdAC17F958D2ee523a2206206994597C13D831ec7`（USDT） |
| value | 0（原生 ETH 没动） |
| nonce | 22 |
| gasPrice × gasUsed | 2.276 gwei × 63,209 ≈ 0.000144 ETH |
| input | `0xa9059cbb` + 收款地址 `0x77c5…fdae` + 金额 `10000000000` |
| 事件日志 | Transfer：`0x0314…73c1` → `0x77c5…fdae`，10,000 USDT |

读法：原生 `value=0` 不代表没转钱，金额在合约日志里；`nonce=22` 表示这个地址历史上一共只发出过 22 笔交易，是个低频地址。同一笔交易，UTXO 链看输入输出，账户模型链要看 `input` 和 `log`，这是两种不同的读法。

## 二、转账里能读出什么

| 字段 | UTXO 链 | 账户模型链 | 研判价值 |
| --- | --- | --- | --- |
| 金额 | 多个输入输出 | 单笔 value | 基础 |
| 时间 | 区块时间 | 区块时间 | 建立时序，做时间窗口关联 |
| 手续费 | 由输入输出差额决定 | Gas price × Gas used | 异常高手续费可能暗示抢跑或特定工具 |
| 找零 | 有，需识别 | 无 | UTXO 聚类的关键 |
| nonce | 无 | 有 | 判断地址年龄与活跃度 |
| Memo / input data | 可写备注 | 合约调用参数 | 交易所充值常带 tag，是非常重要的身份线索 |
| 交易对手 | 输入输出地址 | to 地址 + 日志 | 图谱构建的基础 |

**Memo / Tag 是被低估的线索**：中心化交易所的充值地址往往共用，靠 memo 区分用户。拿到一笔带 memo 的充值，等于拿到了交易所内部的用户标识——这是链上转链下的关键跳板。

#### 链上示例：两种模型，字段怎么读

**UTXO 侧**：交易 [`028873ba…0c30c`](https://mempool.space/tx/028873ba6fa617c77da69796e869fbad614900ff53ba01f0c52e20c7f580c30c)（同区块 976,274）。

| 方向 | 地址 | 金额（sat） |
| --- | --- | --- |
| 输入 1 | `bc1q44vvdhhknnnuda6masg7eky962juk7509ppvrp` | 279,300 |
| 输入 2 | `bc1q0xn96tedgl7cvcane0h56lmgzk2sxcxufeenuc` | 110,000,069 |
| 输出 1 | `bc1q4gvmxpcrkdp2ghs4rmjf7z4p6ejfzukrt06esa` | 216,600 |
| 输出 2 | `bc1qx2stjtrcynelsqlggc533krza90schqcyus3en` | 110,000,000 |

两个输入来自**两个不同地址**，构成一次共同输入；手续费 62,769 sat。但哪个输出是找零？110,000,000 是整数、又接近大额输入的金额，像找零；216,600 更像支付。这只是**推断**，没有地址复用就没有铁证——这正是 UTXO 链上"换新找零地址换隐私"的代价：隐私好了，找零也更难认。

**账户模型侧**：仍用 [`0x7275cd77…cf670`](https://etherscan.io/tx/0x7275cd77d3bb294183b01c88259fc39c6bd2669ef3b1bc49583e5d04e63cf670)，字段拆开看：

- `nonce=22` → 地址年龄与活跃度；
- `gasPrice × gasUsed` → 手续费，异常值可反推工具或抢跑；
- `input` 前 4 字节 `0xa9059cbb` 是 `transfer(address,uint256)` 的选择器，后面两个 32 字节分别是收款地址和金额；
- `log` 里的 Transfer 事件 → 真正的资金流向，**比 `to` 字段可靠**。

::: warning TRON 的 memo 别找错地方
TRON 原生 TRX 转账的 `data` 字段可以带备注；**TRC20 转账本身通常不带 memo**。交易所给的 tag/memo 多数在其内部账本里，链上不一定有。找不到 memo 不等于没有身份线索，要结合充值地址是不是共用地址来判断。
:::

## 三、地址标签体系

链上地址本身不含身份信息。所有"这是某交易所""这是涉诈地址"的判断，都来自**外部标注**。

| 标签来源 | 例子 | 可信度 | 使用注意 |
| --- | --- | --- | --- |
| 项目方公开 | 交易所公布的官方充值地址 | 高 | 需核对官网，别用第三方转述 |
| 浏览器商业标注 | Etherscan、Blockchair 的标签 | 中高 | 来源不透明，重要结论需二次验证 |
| 执法/监管公示 | 制裁名单、公安通报地址 | 高 | 注意名单会更新、会移除 |
| 社区众包 | 各类举报平台 | 低 | 只能当线索，不能当证据 |
| 自行聚类 | 本组分析产出 | 视方法而定 | 必须写明方法、参数、置信度 |

**纪律**：任何材料里出现"该地址为某团伙地址"，必须能回答"标签来源是谁、什么时候标的、依据是什么"。答不上来就改成"该地址被标注为…"。

#### 链上示例：标签挂在合约上，不挂在交易上

稳定币合约是最好核对的一类标签，因为发行方会公开合约地址：

- ERC-20 USDT：`0xdAC17F958D2ee523a2206206994597C13D831ec7`
- TRC-20 USDT：`TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t`
- BEP-20 USDT：`0x55d398326f99059fF775485246999027B3197955`

看 [`0x7275cd77…cf670`](https://etherscan.io/tx/0x7275cd77d3bb294183b01c88259fc39c6bd2669ef3b1bc49583e5d04e63cf670)：交易的 `to` 是 USDT 合约，不是收款人。收款人在日志的第二个 topic 里（`0x77c5…fdae`）。**把合约地址当成交易对手，是新手最常见的错误之一。**

核对一个标签至少四步：

1. 找到一手来源（发行方/项目方官网、监管公告原文），不用第三方转述；
2. 核对合约地址逐字符一致（大小写、链、是否代理合约）；
3. 对照浏览器标签，记录页面快照时间；
4. 在材料里写明"来源 + 核对日期 + 置信度"。

**标签会过期**：交易所换钱包、项目方迁移合约、制裁名单增减，都会让旧标签失效。任何标签引用都必须带时间戳，否则半年后无法复核。

## 四、混币的三种形态

| 形态 | 代表 | 机理 | 留下的痕迹 |
| --- | --- | --- | --- |
| **中心化混币** | 早期混币网站 | 你把币打给它，它从自己的资金池里打给你 | 服务地址本身可被标记；运营方留有内部记录（可调证） |
| **去中心化混币（零知识）** | Tornado Cash 类 | 存款进池，用零知识证明匿名提款 | 合约地址公开；池内关联被切断，但入池/出池时间金额可统计 |
| **协议层隐私** | 隐私币、隐私交易类型 | 转账金额与地址默认隐藏 | 需要专门工具解析；部分交易所直接拒收 |

**只有第二种是当前真正的难题**。第一种可打运营方，第三种可被合规体系排除。

#### 链上示例：Tornado Cash 0.1 ETH 池的一笔存款

- 池合约：`0x12D66f87A04A9E220743712cE6d9bB1B5616B8Fc`（0.1 ETH 池）
- 交易：[`0x9320ae0c…eccde`](https://etherscan.io/tx/0x9320ae0ce4ba4bb95220545eedeab85b7dd3d99c2a4e0770d181fee66b1eccde)（区块 26,434,536）

| 字段 | 值 |
| --- | --- |
| value | 0.1 ETH（正好等于池面额） |
| 方法 | `deposit(address,bytes32,bytes)` |
| gasUsed | 924,652（约为普通 ERC-20 转账的 15 倍，零知识证明的开销） |
| Deposit 事件 | commitment `0x2b43…8388`，leafIndex `76943`，时间戳 2026-11-17 |

读法：**入池是公开的**——金额、时间、commitment 都在链上。出池是另一个地址提交零知识证明，池内"谁对应谁"被切断。所以能做的不是"顺着转账追"，而是：

- 统计同一时间段内入池/出池的金额分布（0.1/1/10/100 ETH 四个池子天然分档）；
- 看出池地址的后续行为（是否直接进交易所、是否跨链）；
- 把"入池前"和"出池后"当作两个独立案件分别溯源，中间用统计关系而非转账关系连接。

::: warning 合规提示
Tornado Cash 曾被美国 OFAC 列入制裁名单（名单状态会变，交互前务必核对最新名单与当地监管口径）。本节只讲机制与痕迹，**不要与受制裁合约交互**；涉案分析应通过公开数据和调证渠道进行。
:::

## 五、跨链桥的机制与断点

跨链桥的本质是**在 A 链锁定资产，在 B 链发行等量凭证**（或反之）。追踪断在"锁"和"发"之间，因为目标链上的凭证来自桥合约，不来自原地址。

| 桥的类型 | 托管方式 | 痕迹 | 追踪可行度 |
| --- | --- | --- | --- |
| 锁定-铸造型 | 中心化或多签托管 | 锁定地址公开，铸造记录公开 | 中（可统计对应关系） |
| 流动性池型 | 两边各设资金池 | 池地址公开 | 中（靠量级与时间匹配） |
| 轻客户端/验证者型 | 链上验证 | 验证交易公开 | 较高 |
| 意图/求解器型 | 第三方撮合 | 撮合路径不公开 | 低 |

**结论**：跨链让"直接转账关系"消失，但没让"统计关系"消失。多条桥叠加使用会显著抬高分析成本，但不会让资金凭空蒸发——**它最终仍要落到某条链上去变现**。

#### 链上示例：从桥合约领回资产

- Wormhole Token Bridge：`0x3ee18B2214AFF97000D974cf647E7C347E8fa585`
- 交易：[`0xeec7ea38…8a2ff`](https://etherscan.io/tx/0xeec7ea38436bb70fe5ab38c0843932ff954d61f67531be4492a298096bc8a2ff)（区块 26,434,774）

| 字段 | 值 |
| --- | --- |
| from | `0x5d9e754a0b0b4271a12e583f37105f35a29a108c` |
| to | 桥合约（不是收款人） |
| 方法 | `completeTransfer(bytes)` |
| gasUsed | 254,090 |
| 日志 | 桥合约事件 + 代币合约的 Transfer |

读法：领币的人调用桥合约，币由桥合约释放/铸造，**付款方不是原链上的转出地址**。所以图上不能画"原地址 → 领币地址"这条边，只能画"原地址 → 桥（锁定）"和"桥 → 领币地址（释放）"两条边，再用金额、时间、链、币种做匹配。

跨链分析的实操顺序：

1. 先在源链确认"入桥"交易（锁定/销毁），记录金额、时间、目标链、目标地址；
2. 在目标链找同一时间窗内由桥合约发出的等额释放；
3. 目标链接收地址再继续做常规溯源；
4. 匹配不上时，考虑是否走了多条桥、是否用了中转地址、是否是意图/求解器型桥。

## 六、OTC 商户的链上画像

OTC 商户（承兑商）是虚拟币与法币之间的兑换节点。他们在链上往往表现出高度重复的模式：

- **地址复用**：长期使用少数几个归集地址，不像普通用户一样每次换新地址
- **高频双向**：既有大量收入也有大量支出，流水规模远超个人使用
- **规律性归集**：按天或按笔数把零散入账归集到主地址
- **与多个 CEX 充值地址交互**：进货和出货都走交易所
- **固定金额段**：常见整数或接近汇率的金额

::: tip 为什么说识别币商比识别单笔交易容易
单笔交易看不出性质，但一个地址连续几个月都在做"收零散、归大额、进交易所"的循环，这个模式本身就说明问题。**行为模式比单点特征稳定得多。**
:::

#### 链上示例：一笔 27.7 万 USDT 的 TRC20 转账能说明什么

交易 [`29cedde7…eb410`](https://tronscan.org/#/transaction/29cedde75ae450da98899818e581125b93d4e477ab2c12c1e7f6c6b3afaeb410)（区块 88,082,202）：

| 字段 | 值 |
| --- | --- |
| from | `TSDcrL8unXb5W7Xq16FdQ6XHVBNvgjsRkE` |
| to | `TG2CMGxnTPgQ6V58kiKd7wbyN8ewtAmY76` |
| 金额 | 277,000 USDT |
| 类型 | TRC-20 Transfer |

单看这一笔，**无法判断**是 OTC 出货、商户归集、还是个人换汇。需要把它放进时间窗里，算四个指标：

| 指标 | 怎么算 | 个人账户 | OTC 商户 | 交易所热钱包 |
| --- | --- | --- | --- | --- |
| 对手方数量 | 30 天内唯一对手方数 | 少（<20） | 多且分散（数百） | 极多（数万） |
| 地址复用 | 同一地址活跃天数 / 30 | 低 | **高** | 高 |
| 双向流水比 | 收入笔数 / 支出笔数 | 接近 1 或单向 | 接近 1，且两边都大 | 接近 1，量级极大 |
| 与 CEX 交互占比 | 与已知交易所地址的笔数占比 | 偶发 | **稳定、周期性** | 本身就是 CEX |

判读顺序：先看**对手方结构**（是海量散户还是少数固定地址），再看**时间规律**（是否按天归集），最后看**资金出口**（是否稳定流向交易所或法币通道）。三项都吻合，才写"符合 OTC 商户行为特征"，不要直接写"该地址是币商"。

## 七、资金分层清洗的标准结构

这是本组的核心模型。实务中的案子基本都能套进这五层，只是层数会简化或合并。

| 层级 | 作用 | 典型特征 | 研判切入点 |
| --- | --- | --- | --- |
| **L1 收款层** | 直接收被害人钱 | 一次性地址、金额零散、与被害人钱包一一对应 | 与报案记录比对，锁定起算点 |
| **L2 拆分层** | 打散资金、混同资金来源 | 小额多笔、地址众多、频繁新建 | 短时间内的扇形分散 |
| **L3 归集层** | 汇总到少数地址统一处理 | 多进少出、金额趋于整数、地址稳定复用 | 扇形收敛点，是抓人的关键位置 |
| **L4 清洗层** | 切断关联 | 混币、跨链、交易所对倒 | 入池/出池统计分析 |
| **L5 变现层** | 变成可用资金 | OTC 出货、境外取现、购买实物 | 与法币出口的对接点 |

**为什么 L3 最关键**：拆分层可以无限扩张（多招卡农就行），但归集层必须收敛，否则运营成本无法控制。**收敛点是这套结构的结构性弱点**，也是打击的最佳着力点。

### 五层结构 + 对应链上特征

```text
被害人钱包 / 报案记录
        │  一次性地址、金额与报案一一对应
        ▼
┌──────────────────────────────────────────────┐
│ L1 收款层   特征：地址一次性、单笔金额小、时间密集 │
│             指标：唯一收款地址数、首笔时间        │
└──────────────────────────────────────────────┘
        │  扇形分散：小额多笔、批量新建地址
        ▼
┌──────────────────────────────────────────────┐
│ L2 拆分层   特征：地址数暴涨、单地址余额低        │
│             指标：24h 新建地址数、扇出度、平均单笔 │
└──────────────────────────────────────────────┘
        │  扇形收敛：多进少出、金额趋整、地址复用
        ▼
┌──────────────────────────────────────────────┐
│ L3 归集层 ★ 特征：少数地址长期复用、入度远大于出度 │
│             指标：入度/出度比、余额集中度、归集周期 │
└──────────────────────────────────────────────┘
        │  混币 / 跨链 / 交易所对倒
        ▼
┌──────────────────────────────────────────────┐
│ L4 清洗层   特征：直接转账边断开，统计关系仍在     │
│             指标：池入/出金额时间分布、桥锁定/释放  │
└──────────────────────────────────────────────┘
        │  OTC 出货、境外取现、购买实物
        ▼
┌──────────────────────────────────────────────┐
│ L5 变现层   特征：与法币出口或实物消费对接        │
│             指标：CEX 充值地址+tag、OTC 对手方    │
└──────────────────────────────────────────────┘
```

| 层级 | Bitcoin 上的样子 | 账户模型链上的样子 | TRON 上的样子 |
| --- | --- | --- | --- |
| L1 | 一次性 P2PKH/P2WPKH 地址 | 新地址、首笔由他人代付 gas | 新激活地址、首笔能量由他人委托 |
| L2 | 一笔多输出扇出，找零回原地址 | 批量转账合约/脚本，nonce 连续 | 批量 TRC-20 转账，带宽消耗集中 |
| L3 | 多输入合并、找零集中 | 归集地址 nonce 极高、余额集中 | 归集地址长期复用、能量持续质押 |
| L4 | CoinJoin、跨链桥锁定地址 | Tornado 类池、桥合约 | 桥合约、交易所对倒 |
| L5 | 交易所充值地址 | CEX 充值地址 + tag | CEX 充值地址 + memo/tag |

::: tip 图怎么用
从 L1 往 L5 走是"顺查"，从 L5 往 L1 走是"倒查"。图上每一条边都要能回答"金额、时间、地址、交易哈希"四件事，答不上来的边就是假设，不要画成实线。
:::

#### 链上示例：L4 的两个真实断点

用公开基础设施演示 L4 长什么样（只演示结构，不指认案件）：

1. **混币断点**：0.1 ETH 进入 Tornado 池（[`0x9320ae0c…eccde`](https://etherscan.io/tx/0x9320ae0ce4ba4bb95220545eedeab85b7dd3d99c2a4e0770d181fee66b1eccde)），出池是另一地址 + 零知识证明；
2. **跨链断点**：目标链上调用 Wormhole 桥 `completeTransfer`（[`0xeec7ea38…8a2ff`](https://etherscan.io/tx/0xeec7ea38436bb70fe5ab38c0843932ff954d61f67531be4492a298096bc8a2ff)），币由桥合约释放。

L1–L3 的示例必须来自具体案件数据，不能拿公开基础设施硬套；本页只保证"L4 的边怎么画"是可复现的。

## 八、主流链差异速查

| 链 | 模型 | 主要稳定币 | 特点 | 研判注意 |
| --- | --- | --- | --- | --- |
| Bitcoin | UTXO | 无原生稳定币 | 手续费按字节，确认慢 | 聚类靠共同输入，找零识别关键 |
| Ethereum | 账户 | USDT-ERC20、USDC | Gas 高，合约生态最全 | 合约日志信息丰富，是优势 |
| TRON | 账户 | **USDT-TRC20** | 转账成本极低、确认快、地址以 T 开头 | **涉诈资金最主流载体**，必须重点覆盖 |
| BSC | 账户 | USDT-BEP20 | 成本低，土狗币多 | 发币门槛极低，资金盘高发 |
| Solana | 账户 | USDC 为主 | 高吞吐、低费用 | 数据模型特殊，工具支持弱于 EVM |

::: warning TRON 为什么必须单列
TRON 上的 USDT 转账成本极低、到账快、地址申请零门槛，是当前涉诈涉赌资金最集中的载体。做链路分析只做以太坊，等于漏掉了一大半。**工具选型和数据集收集都要把 TRON 放在第一优先级。**
:::

### 链上示例：同一个动作，五条链上的差别

| 链 | 示例 | 关键字段 | 能看出什么 |
| --- | --- | --- | --- |
| Bitcoin | [`028873ba…0c30c`](https://mempool.space/tx/028873ba6fa617c77da69796e869fbad614900ff53ba01f0c52e20c7f580c30c) | 2 输入 / 2 输出 / 手续费 62,769 sat | 找零要靠推断 |
| Ethereum | [`0x7275cd77…cf670`](https://etherscan.io/tx/0x7275cd77d3bb294183b01c88259fc39c6bd2669ef3b1bc49583e5d04e63cf670) | nonce 22 / gasUsed 63,209 / Transfer 日志 | 地址年龄 + 真实收款人 |
| TRON | [`ad54d36f…4532b`](https://tronscan.org/#/transaction/ad54d36fe5940c77dc8fd583f6020d960120216bc0cc049dd95bf4f38444532b) | 能量 64,285 / 带宽费 0.345 TRX / 352,461.93 USDT | 费用由资源决定，不看 gas |
| BSC | [`0x13707c63…a69a6a`](https://bscscan.com/tx/0x13707c635ea7e629f182b718ad4f890da1bc41d564d5d758d5f6520073a69a6a) | gasPrice 0 / gasUsed 34,515 / 50 USDT | 手续费可以为零 |
| Solana | [`jTFERv3S…DA7y`](https://solscan.io/tx/jTFERv3SPHjnHyzafSZLZuRNGV37Gir1EJC3vRoshoXrHt8smgfrvtiCjbbEzPVrnqhDHGQjEYbfgitqxoWDA7y) | 签名即交易 ID / 无 nonce / 按计算单元计费 | 不能套 EVM 的读法 |

三个容易踩的坑：

- **Solana 的交易 ID 是签名（base58），不是哈希**，长度和字符集都不同，别用十六进制工具去校验；
- **BSC 允许 gasPrice=0**，看到手续费为零不要当成数据缺失；
- **TRON 的交易没有 nonce**，地址年龄要看首笔交易时间和累计交易数。

## 九、地址聚类：方法与误报率

聚类不是"确认同一人"，是**在给定方法下，判断若干地址是否由同一控制实体支配的概率性结论**。方法、参数、样本、置信度四样缺一不可。

### UTXO 链：三条主线索

| 线索 | 规则 | 强度 | 主要误报来源 |
| --- | --- | --- | --- |
| 共同输入 | 同一笔交易的多个输入属于同一控制方 | 强 | 混币、交易所/矿池批量归集、托管服务 |
| 找零识别 | 找零输出回到自己控制的地址 | 中 | 地址复用少、钱包换址策略 |
| 行为指纹 | 时间、金额、手续费、输出顺序高度相似 | 弱 | 自动化工具、批量脚本 |

找零识别可以按信号强弱排序（实际使用时至少命中两条再下结论）：

1. **地址复用**：找零回到某个输入地址，最强；
2. **脚本类型**：输入是 P2WPKH，找零输出也是 P2WPKH，而收款方是 P2PKH；
3. **整数金额**：支付金额多为整数，找零常带零头；
4. **输出顺序**：部分钱包固定把找零放在最后（或最前），但会随版本变化；
5. **手续费反推**：按字节费率反推交易大小，判断哪个输出"多出来"。

::: warning 先剔除，再聚类
做共同输入之前，先把已知的混币交易、交易所批量归集、矿池出块奖励、托管服务地址剔除。不剔除就聚类，等于把成千上万个用户合成一个"实体"，后面所有结论都会错。
:::

### 账户模型链：没有共同输入，靠关系线索

| 线索 | 规则 | 强度 | 说明 |
| --- | --- | --- | --- |
| gas 代付 | 新地址首笔交易的 gas 由 A 支付 | 中强 | 常见于批量养号、空投农场 |
| 首笔资助 | A 向新地址转入第一笔小额资金 | 中 | 需排除交易所提现 |
| nonce 连续性 | 多地址 nonce 连续、时间间隔固定 | 中 | 批量脚本特征 |
| 合约关系 | 同一部署者、同一 `owner()`、同一实现合约 | 强 | 代理合约要穿透到实现 |
| 授权关系 | A 对多个地址有 `approve` 权限 | 中 | 授权钓鱼的常见结构 |
| 充值地址 + tag | 同一 CEX 充值地址 + 不同 tag | 强 | 能直接落到交易所内部用户 |
| 地址复用 | 长期使用同一地址收付 | 中 | TRON/BSC 用户复用率高于 ETH |

这些线索只能说明"存在关系"，不能直接说明"同一人"。比如 gas 代付可能是交易所代付、可能是赞助方、也可能是批量工具。

### 误报率怎么谈

误报率（假阳性率）不是固定常数，**它取决于数据集、链、时间窗和方法参数**。公开文献里的数字不能直接搬到自己的案子上。可操作的做法：

1. **自建标注集**：抽 50–100 个已知实体的地址（交易所、项目方、已判决案件），当作 ground truth；
2. **算两个指标**：精确率（聚出来的簇里有多少是真的）和召回率（真实实体有多少被聚到）；
3. **记录误差方向**：交易所批量归集会让簇"过大"（假阳性），CoinJoin 会让簇"过小"（假阴性），报告里要写明偏向哪一侧；
4. **交叉验证**：高风险结论至少用两种独立方法（如共同输入 + 找零 + 行为指纹）互相印证；
5. **人工复核**：对进入报告的簇逐个人工看交易，抽样比例和复核结果写进附录。

| 常见误报 | 触发条件 | 缓解手段 | 残余风险 |
| --- | --- | --- | --- |
| 把交易所归集当成个人 | 批量提现、热钱包归集 | 剔除已知服务地址 | 未标注的小型交易所 |
| 把混币当成同一人 | CoinJoin、混币池 | 识别混币特征并剔除 | 新型混币协议 |
| 把批量脚本当成同一人 | 空投农场、批量养号 | 结合 gas 来源与行为 | 脚本刻意打散 |
| 把代付当成控制关系 | 交易所代付、赞助方 | 查代付方历史行为 | 代付方本身是中介 |

**表述模板**（直接抄）：

> 地址 A 与地址 B 在 2026-01-01 至 2026-06-30 期间，通过共同输入启发式（样本 12 笔，人工复核 12/12）被判定为同一控制实体，置信度：中高。已知偏差：该时段内未发现混币交易。

反过来，写"该地址为某团伙地址"而给不出方法、样本和复核记录，就是把线索当结论。

## 十、TRON 专节：能量、带宽与地址格式

TRON 是涉诈资金最集中的链，但它的账户模型和以太坊差别很大，工具和读法都不能照搬。

### 地址格式

- TRON 地址 = `0x41` + 20 字节公钥哈希，再做 Base58Check 编码，所以**以 T 开头、固定 34 个字符**；
- 十六进制形式是 `41` 开头的 21 字节，例如 `41...`；EVM 地址是 `0x` + 20 字节；
- 两者可以互转：去掉 `0x41` 前缀 / 去掉 `0x` 前缀，但**不能直接混用**，很多工具会静默截断。

::: warning 别把 TRON 地址贴到 Etherscan
Etherscan 查不到 T 开头的地址，会当成非法输入。TRON 用 Tronscan，BSC 用 BscScan，Solana 用 Solscan。链选错了，数据源就错了。
:::

### 账户激活

TRON 的新地址首次收到 TRX 时会被**激活**，激活会消耗少量 TRX（具体费用由链参数决定，以 Tronscan 显示为准）。只有 TRC-20 余额、没有 TRX 的地址可能仍处于未激活状态，不能主动发起交易。

研判价值：**谁给新地址打了第一笔激活费，谁就与它有资助关系**。批量养号常出现"一个地址给几十个新地址各打一点点 TRX"的扇形结构。

### 两种资源：带宽与能量

| 资源 | 用途 | 免费额度 | 不够时 |
| --- | --- | --- | --- |
| 带宽（Bandwidth） | 按交易字节数消耗，所有交易都要 | 每个已激活账户每天有少量免费额度 | 燃烧 TRX |
| 能量（Energy） | 合约执行消耗，TRC-20 转账必须 | 无免费额度 | 质押 TRX 获取，或燃烧 TRX |

关键差别：**以太坊用 gas 一次性付费，TRON 用"资源"预付**。质押 TRX 换能量后，TRC-20 转账可以只付很少的带宽费，甚至接近零成本。这就是 TRON 上小额高频转账泛滥的原因之一。

TRC-20 转账的能量消耗大致分两档：

- 收款地址**已经持有**该代币：约 3 万能量；
- 收款地址**从未持有**该代币（需要初始化余额）：约 6 万能量。

同一笔转账，收款方状态不同，成本能差一倍。

### 资源委托：TRON 特有的关系线索

能量和带宽可以**委托**给其他地址（Delegate Resource），也可以随时撤销。这让 TRON 上出现一种以太坊没有的信号：

> A 持续给 B 委托能量 → A 在为 B 的合约调用买单。

这比以太坊的"gas 代付"更明确，因为委托关系在链上是显式的、可枚举的。分析批量地址时，**按"能量委托方"分组**，经常能直接分出不同的运营团伙。

### 交易结构

- **TRX 原生转账**：`TransferContract`，看 `owner_address`、`to_address`、`amount`，备注在 `data` 字段；
- **TRC-20 转账**：`TriggerSmartContract`，调用 USDT 合约的 `transfer`，真实金额和收发方在事件日志里；
- **内部交易**：合约内部调用产生的转账，浏览器会单列，别只看主交易。

### 链上示例：一笔 35 万 USDT 的 TRC-20 转账

交易 [`ad54d36f…4532b`](https://tronscan.org/#/transaction/ad54d36fe5940c77dc8fd583f6020d960120216bc0cc049dd95bf4f38444532b)（区块 88,082,012）：

| 字段 | 值 |
| --- | --- |
| from | `TKYtXaopx7C6uPW1RFRX1jo25EAJUC3sST` |
| to（合约） | `TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t`（USDT） |
| 金额 | 352,461.93 USDT |
| 能量消耗 | 64,285 |
| 能量费 | 0（由质押/委托的能量覆盖） |
| 带宽费 | 0.345 TRX |

读法：这笔交易没有消耗 TRX 买能量，说明发送方有可用能量（自己质押或别人委托）。**看到"能量费为 0"，要追问能量从哪来**——自己质押是常规操作，别人委托则是一条关系线索。

### TRON 分析的常见坑

- 用 nonce 判断地址年龄（TRON 没有 nonce）；
- 只查 TRX 余额，忽略 TRC-20 余额（涉诈资金几乎都在 USDT 上）；
- 把能量当 gas，按以太坊的费率去估算成本；
- 忽略能量委托记录，漏掉团伙之间的资助关系；
- 地址格式不做转换，直接跨链查询。
