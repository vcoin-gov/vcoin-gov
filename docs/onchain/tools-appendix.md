# 实测与自建附录

## 结论先行

1. 【事实｜[Tronscan API 文档](https://docs.tronscan.org/en/api/common-network-auth)】**TRON 必须带 Key**：请求头 `TRON-PRO-API-KEY`，部分端点无 Key 直接 401。**配额公开资料未披露**，所以 Tronscan 只能人工核对，不进自动化批量。
2. 【事实｜[graphsense.org](https://graphsense.org)】GraphSense 的 adapter 覆盖 BTC / BCH / LTC / ZEC / ETH / **Tron**，**没有 BSC adapter**。自建能覆盖 TRON，补不上 BSC。
3. 【决策｜2026-11-13】**GraphSense 本期不建设**。三条理由：覆盖缺口落在主战场；数据导入与索引以「天」计；标签体系只能按月攒。无节点运维人力是压死这条路的最后一根稻草。
4. 【决策】BSC 走 0 成本路线（网页核对 + 公开通报地址抽样），代价是**只能到个案级，不能支撑分布级结论**。
5. 【待填】五工具标签横评的样本地址已选定（见第四节），**网页版查询不需要注册**，任何组员用浏览器 20 分钟可填完；本页不代人填。

## 一、TRON 生态：公开资料能确认什么

【推断｜置信度：中】TRON 是 USDT 涉诈资金的主要承载链之一，所以 Tronscan 不是「备选」而是**基线工具**，但它的 API 已进入 Key 时代。

| 项目 | 公开资料可确认 | 公开资料未披露 |
| --- | --- | --- |
| 鉴权 | 必须带 Header `TRON-PRO-API-KEY`；部分端点无 Key 返回 401【事实】 | Key 分档的具体配额（官方仅提及「四个档位」） |
| 端点覆盖 | 有 `/api/internal-transaction`、`/api/token_trc20/transfers` 等内部转账与 TRC20 流水接口【事实】 | 单页返回条数上限、历史可回溯深度 |
| 限流 | 官方称无 Key 会限流【事实】 | 请求数/分钟、日上限、并发数 |
| 生态工具 | 官方另提供 MCP / CLI 入口【事实】 | 与网页版标签是否同源 |

【推断｜置信度：高】在上表右列补齐之前，Tronscan 的定位就是**人工核对工具**。这不是保守，是因为「不知道额度」这件事本身就决定了不能拿它做批量。

## 二、GraphSense：覆盖判断与不建设理由

【事实｜[graphsense.org](https://graphsense.org)】架构为 Spark + Cassandra，解析用 BlockSci，MIT 许可；TagPack 体系可公开可私有；另有第三方（Iknaio）提供托管实例，不想运维也可用。

| 链 | 是否有 adapter | 对本案的意义 |
| --- | --- | --- |
| BTC / BCH / LTC / ZEC | 有 | 覆盖传统币种链路 |
| ETH | 有 | 覆盖 EVM 主链 |
| TRON | 有 | 能覆盖一半主战场 |
| BSC | **无** | 补不上另一半，仍需 BscScan / Blockscout |
| 新增链 | 需自行实现 adapter | 等于自己再开发一轮 |

【决策｜2026-11-13】**不建设。** 理由按权重排：① 缺口（BSC）正好落在主战场，自建的边际价值被削掉一半；② 数据导入与索引构建以「天」计，不是一次性投入；③ 标签积累买不到，只能按月攒；④ 组内没有能长期盯节点的人。

成本框架保留在这儿，**只作为将来条件变化时的预案**，不是报价，数值均为【推断｜依据：公开链数据体量与 Spark/Cassandra 常驻需求；置信度：低】：

| 成本项 | 需要测什么 | 量级预估 | 收益 |
| --- | --- | --- | --- |
| 存储 | 目标链全量数据落地体积 | BTC 级别已需 TB 量级，加 ETH / TRON 成倍上升 | 原始数据可复现 |
| 算力 | 解析与索引耗时、常驻内存 | 单机 16–32 核 / 64–128 GB 起步 | 支持多跳聚类 |
| 时间 | 从零到能查第一次的周期 | 以「天」计 | —— |
| 标签 | 从零积累 TagPack 的来源与人工 | 无法预估，只能按月累积 | 标签可审计（核心价值） |
| 运维 | 升级、重建索引、故障恢复 | 需固定 1 人兼职 | 长期可持续 |

**重启条件**：有了稳定运维人力，且 BSC 侧的 adapter 缺口有了现成解法（官方或社区实现），两个条件同时满足才重启评估。
