## 本页要回答的问题

1. **资金树**和**资金流转图**有什么本质区别？什么时候用哪个？
2. 上万个节点怎么画才不糊成一团？聚合、折叠、时间切片各适合什么场景？
3. 布局算法怎么选？力导向好看但不可读，分层布局可读但会丢信息——怎么权衡？
4. 一张图要能当**证据**用，需要满足什么条件？（这是和"好看的图"的根本区别）
5. 原型用什么技术栈？自建还是接现成可视化库？

::: tip 先定一个判断标准
可视化的目的不是让图好看，是让**结论可验证**。任何一张图，如果读者无法从图上复算出一个数字，这张图就只能当封面，不能当证据。
:::

## 一、两种图，别混用

这是本页最重要的一节。实务中最常见的问题是把两种图混着做，结果两边都不达标。

| 维度 | 资金树（Fund Tree） | 资金流转图（Flow Graph） |
| --- | --- | --- |
| 结构 | **树**，无环，一个根 | **有向图**，允许环路与汇聚 |
| 起点 | 固定（被害人地址 / 案件地址） | 任意或全体 |
| 展开方式 | 按跳数（1 跳、2 跳、3 跳） | 按资金关联自然形成 |
| 回答的问题 | 这笔钱去了哪、经过几层 | 这帮人怎么组织的、谁在中间 |
| 主要用途 | **举证、汇报、还原单案** | **发现团伙结构、找归集点** |
| 缺点 | 合并账户画不出（同一地址多次出现） | 节点爆炸，可读性差 |
| 典型规模 | 几十到几百节点 | 几千到几万节点 |

**一句话区分**：资金树是**追一笔钱**，资金流转图是**看一伙人**。

::: warning 资金树的常见错误
把同一地址在不同跳数重复画出来，看起来是树，实际是图——这会让读者误以为有多条独立资金流。正确做法是**同一地址只出现一次，用连线表示多跳关系**，或者在节点上标注"第 N 跳再次出现"。
:::

## 二、规模问题：万级节点怎么画

节点一多就糊，这是绕不过去的。四种处理方式，各有代价：

| 方法 | 做法 | 适合场景 | 代价 |
| --- | --- | --- | --- |
| 阈值裁剪 | 只画金额 ≥ X 的边 | 快速定位主干路径 | 小额拆分结构被隐藏（而小额拆分本身就是特征） |
| 地址聚合 | 把聚类后的一簇画成一个节点 | 团伙结构展示 | 丢失簇内细节，聚合本身有误差 |
| 分层折叠 | 按 L1–L5 层聚合，逐层展开 | 讲清结构 | 交互复杂，不适合静态截图 |
| 时间切片 | 按时段分别成图 | 展示资金推进过程 | 跨时段的关联看不到 |

**建议组合**：**先聚合再展开**。默认视图按聚类折叠成一簇一簇，点开某簇才展开内部地址。这样首屏能看懂结构，细节按需下钻。

## 三、布局怎么选

| 布局 | 效果 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 力导向（force-directed） | 节点互相排斥、边像弹簧 | 自然、能看出社团 | 每次渲染结果不同，**不能当证据** |
| 分层（dagre / 层级） | 从上到下按跳数排列 | 可读、可复现、像资金树 | 环路处理难看 |
| 环形 / 径向 | 以根为中心向外扩散 | 适合星形结构的资金盘 | 深链路会重叠 |
| 地理/时间轴 | 按时间排布 | 展示节奏 | 空间关系丢失 |

**结论**：**举证用分层布局，探索用力导向**。同一个数据集可以出两张图，用途不同。凡是进报告、进证据的图，必须用确定性布局（同样的数据，任何人生成出来都一样）。

## 四、技术选型

| 方案 | 定位 | 适合 | 不适合 |
| --- | --- | --- | --- |
| **Cytoscape.js** | 专用图可视化库 | 千级节点、需要丰富布局与交互 | 需要炫酷动效的展示 |
| **AntV G6** | 图可视化引擎，中文文档 | 快速搭原型、需要开箱即用交互 | 超大规模性能瓶颈 |
| **ECharts graph** | 通用图表库的图类型 | 简单关系图、和已有 ECharts 项目集成 | 复杂交互 |
| **D3.js** | 底层可视化库 | 完全自定义 | 开发成本高，不划算 |
| **Graphviz** | 命令行布局 | 生成静态证据图（确定性布局） | 交互 |
| **Neo4j Bloom / 浏览器** | 图数据库自带可视化 | 已有 Neo4j 时顺手用 | 许可与部署成本 |

**推荐路线**：数据侧用 **NetworkX** 做图计算（最短路、社区发现、中心度），渲染侧用 **Cytoscape.js** 或 **G6** 做交互原型，出报告时用 **Graphviz 生成确定性布局的静态图**。

这样分工的好处：计算和渲染解耦，换渲染层不影响分析逻辑。

## 五、让图能当证据的四条要求

| 要求 | 具体做法 |
| --- | --- |
| **可复现** | 数据快照固定（写明区块高度或抓取时间），布局确定性，任何人重跑得到同一张图 |
| **可溯源** | 每条边都能点开看交易哈希，图上标注金额单位与精度 |
| **可复算** | 图上要有汇总数字（总流入、总流出、跳数），读者能对得上 |
| **标注清楚** | 地址标签注明来源与时间；推断的边用虚线；聚类节点注明置信度 |

**反例**：一张漂亮的力导向图，没有时间戳、没有交易哈希、节点不标金额——这在法庭上没有意义。

## 六、团伙资金分层模式怎么画

这是可视化里最有价值的一类图。不要画全量图，画**结构图**：

```
被害人池 ──▶ L1 收款地址（一次性，大量）
                  │
                  ▼
            L2 拆分地址（扇出，数量激增）──▶ 部分回流
                  │
                  ▼
            L3 归集地址（扇入，数量收敛）◀── 关键节点
                  │
                  ▼
            L4 清洗（混币 / 跨链 / 交易所）
                  │
                  ▼
            L5 变现（OTC / 境外）
```

画的时候要突出三件事：

1. **收敛点在哪**（L3）——这是打击着力点
2. **扇出宽度**（L2）——反映组织规模
3. **时间跨度**——从 L1 到 L5 用了多久，反映专业程度

## 七、原型开发计划

分阶段，别一上来就做全套。

| 阶段 | 目标 | 产出 | 判断标准 |
| --- | --- | --- | --- |
| P0 | 静态图 | 手绘/Graphviz 出一张标准五层结构图 | 别人能照着看懂 |
| P1 | 单案资金树 | 输入一个地址，展开 3 跳，可交互 | 能替代手工画图 |
| P2 | 图谱聚合 | 万级节点按聚类折叠，可下钻 | 首屏 3 秒内渲染完成 |
| P3 | 时间轴播放 | 按时间推进展示资金流动过程 | 能看出节奏与阶段性 |

::: tip 建议从 P0 开始
一张手画的标准结构图，价值高于一个跑不动的原型。先把"该画成什么样"定下来，再写代码。
:::
